---

## ទិដ្ឋភាពទូទៅ (Overview)

លំហូរការងារ `/debug` អនុវត្ត **ពិធីការស៊ើបអង្កេត ៤ ដំណាក់កាល** (Discovery, Hypothesis, Verification, Resolution)។ វាការពារការកូដបែបស្មានៗ ដោយតម្រូវឱ្យមានភស្តុតាងជាក់ស្តែងមុនពេលកែប្រែកូដ។

<Callout type="info" title="ពេលណាត្រូវប្រើ៖">
  - "ចុចប៊ូតុង Login តែគ្មានអ្វីកើតឡើងទាល់តែសោះ"
  - "API ឆ្លើយតប error 500 មិនទៀងទាត់"
  - "កម្មវិធីគាំងតែនៅលើ mobile ប៉ុណ្ណោះ"
</Callout>

---

## ដំណើរការការងារ (The Process)

<StepList>
  <Step number={1} title="ការស្វែងរកការពិត (Discovery)">
    ប្រមូលការពិត៖ error logs, របាយការណ៍អ្នកប្រើប្រាស់, ជំហានបង្កបញ្ហា។

    ```bash
    /debug Login returns 403 even with correct credentials
    ```
  </Step>
  <Step number={2} title="ការបង្កើតសម្មតិកម្ម (Hypothesis)">
    កំណត់មូលហេតុដែលអាចកើតមាន ផ្អែកលើភស្តុតាង និងលទ្ធភាពខ្ពស់។
  </Step>
  <Step number={3} title="ការផ្ទៀងផ្ទាត់ (Verification)">
    ធ្វើតេស្តសម្មតិកម្មនីមួយៗជាប្រព័ន្ធតាមរយៈស្គ្រីប ឬ log ដាច់ដោយឡែក។
  </Step>
  <Step number={4} title="ការដោះស្រាយ (Resolution)">
    អនុវត្តការកែកូដឱ្យចំគោលដៅ និងបន្ថែមតេស្ត regression ស្វ័យប្រវត្តិ។
  </Step>
</StepList>

## គន្លឹះមានប្រយោជន៍ (Pro Tips)

<ProTips>
  <Tip title="ផ្តល់បរិបទឱ្យបានច្បាស់">
    ចម្លង error message ឬ stack trace ជាក់ស្តែងដាក់ក្នុង prompt ដើម្បីឱ្យការស្វែងរកការពិតកាន់តែលឿន។
  </Tip>
  <Tip title="ជឿជាក់ ប៉ុន្តែត្រូវផ្ទៀងផ្ទាត់">
    ប្រាប់ភ្នាក់ងារឱ្យដំណើរការករណី reproduction ម្តងទៀត ដើម្បីបញ្ជាក់ថាកំហុសត្រូវបានដោះស្រាយពិតប្រាកដ។
  </Tip>
</ProTips>
